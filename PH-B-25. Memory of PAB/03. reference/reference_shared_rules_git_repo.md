**`00. rules/` 는 사본이 아니라 깃 작업본이다.** 팹·세리 양쪽의 `memory/00. rules/` 가 같은 깃허브 저장소를 가리킨다 (260814 배선).

| 항목 | 값 |
|---|---|
| 저장소 | `psw95master/PH-A-9` — **비공개** |
| 웹 | https://github.com/psw95master/PH-A-9 |
| 도구 | `rules-sync` (양 맥 `~/.local/bin/`) |
| 자동 실행 | `SessionStart` 훅 — 세션 시작 때 **받아오기만** |

**쓰는 법**
1. `rules-sync` — 받아오기. 훅이 자동으로 돌리므로 손으로 칠 일은 거의 없다.
2. `rules-sync push "무엇을 왜 고쳤는지"` — 고친 내용 올리기. **커밋은 자동이 아니다.**

**Why 깃인가 (가상본·심링크를 기각한 이유):** 두 맥은 물리적으로 다른 기기라 심링크가 기기를 건너뛰지 못한다. 실물을 iCloud/드라이브에 두면 건너뛸 수는 있으나, **260730 에 정확히 그 구조로 `~/.claude/skills/` 심링크 4개가 끊겨 2주간 죽어 있었다** (26맥은 지금도 빈 폴더다 → [[cerry-link-symlink-recovery]]). 규칙 파일은 **매 세션 시작 때 읽는 파일**이라, 끊겨도 에러가 아니라 "조용히 규칙 없이 시작"이 된다. 티가 안 나는 실패가 제일 위험하다.

**Why 자동 커밋을 안 하나:** 무엇이 왜 바뀌었는지 남기려고 깃을 골랐는데, 자동 커밋은 이력을 `auto: 260814` 로 채워 그 목적을 없앤다. 올리는 것은 사람이 이유를 적을 때만.

**⚠️ 걸려 넘어질 자리 2가지**
1. **`cerry-export` 에 `.git/` 제외를 넣어뒀다.** 안 넣으면 깃 이력 폴더가 통째로 구글 드라이브 사본에 딸려 올라간다.
2. **26맥은 HTTPS(`gh` 로그인), 19맥은 SSH 키로 붙는다.** 26맥의 SSH 키는 깃허브에 등록돼 있지 않다 — 26맥에서 SSH 원격으로 바꾸면 인증이 깨진다.

**메모리와 헷갈리지 말 것.** 규칙(`00. rules/`)은 셋이 **같아야** 하므로 한 벌·공유다. 메모리(`01./02./03.`)는 기기마다 **달라야** 하므로 각자 로컬이고 드라이브로 사본만 나간다 ([[device-split-memory]]). 반대편 메모리를 고칠 때의 원칙은 [[feedback-other-agent-memory-merge-not-replace]] 참고.
