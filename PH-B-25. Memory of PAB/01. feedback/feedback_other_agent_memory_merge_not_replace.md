**반대편 기기(팹↔세리)의 메모리 파일을 고칠 때, 내 쪽 같은 이름 파일을 복사해 덮어쓰지 않는다.** 그쪽 원문을 **한 글자도 건드리지 않고** 그대로 둔 채, 교정·추가 내용은 **위쪽 블록으로만 얹는다.**

260814에 세리의 `feedback_guide_file_versioning.md` 를 팹 버전 기반으로 새로 써서 scp 로 덮어썼다. 페리가 **"19맥에서 가져온 거 맞아, 아니면 네 메모리를 복사해 붙인 거야?"** 라고 물어 드러났다.

**Why:** 같은 이름이어도 두 기기의 메모리는 각자 다른 대화에서 자란 별개 파일이다. 세리 파일에만 있던 예시 파일명(`PSW-C-2_…_v1.0.md`)과 "버전 접미사는 **파일명** 규칙이라 폴더명 개편의 영향을 받지 않는다"는 주석이 통째로 사라졌다. 260729 R&R 개편이 메모리를 갈라놓은 이유가 바로 **"한 파일에 쓰는 주체가 하나면 충돌이 없다"** 인데, 내가 그 경계를 넘어 덮어쓴 것이다 ([[device-split-memory]]).

**더 나쁜 점:** scp 는 메모리 도구가 아니라서 `.overwritten/` 백업이 남지 않는다. 마침 같은 대화에서 원문을 읽어둔 덕에 복구했지, 안 읽었으면 되돌릴 방법이 없었다.

**How to apply:**
1. 고치기 전에 **반드시 그쪽 원문을 먼저 읽는다.** 읽지 않은 파일은 덮어쓰지 않는다.
2. 원문 본문은 그대로 두고, 교정은 맨 위 인용 블록(`> 🔴 260814 교정 …`)으로 얹는다. 본문의 낡은 표현은 지우지 말고 **"이건 이렇게 읽으라"**고 블록에서 지시한다.
3. 공유해야 하는 **규칙 문서**(`00. rules/STYLE.md`, `DESIGN.md`)는 예외 — 셋이 같은 내용을 써야 하므로 복사가 맞다. 헷갈리지 말 것: **규칙 문서는 복사, 메모리 파일은 병합.**
4. 반대편 파일을 고쳤으면 무엇을 어떻게 고쳤는지(덮어쓰기인지 얹기인지) 페리에게 명시한다.

관련: [[memory-files-stay-split]] (파일을 합치지 않는다) — 이건 기기 간 덮어쓰기 금지라 다른 축이다.
